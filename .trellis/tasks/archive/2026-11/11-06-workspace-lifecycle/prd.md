# 目标

swarm 运行期间为提取代码而注册的临时工作区不再长期留在 DSH 里：swarm 结束时统一清理它们的注册；启动页的工作区下拉只显示长期使用的工作区；并提供每个 swarm 的任务状态数据供会话页状态条使用。

# 要求

- 记录每个 swarm 因会话创建而新增的工作区（主会话工作区与各子任务 worktree 工作区），能区分「本次新建」与「复用已有」，绝不能删除用户原有工作区。
- swarm 结束（完成或手动结束）时删除这些新建工作区的注册；删除不触碰目录、worktree 与已写入的会话日志；删除失败要记录并不阻断完成流程。
- 启动页工作区列表只包含长期使用的工作区（复用已有的注册），排除 swarm 运行期间新建的临时工作区。
- 为面板与会话页提供每个 swarm 的任务状态：在跑、待跑/待派发、刚结束的数量与最近一条变化；数据来自现有 Ticket 状态，不新增持久化来源。
- 迁移或重启后，已完成 swarm 遗留的临时工作区注册也要能识别并清理。

# 验收

- 新建 swarm 跑完若干子任务后结束，DSH 工作区列表中不再出现这些 worktree 工作区；原有用工作区与目录不受影响。
- 启动页下拉不出现临时工作区，仍能选择长期工作区。
- 状态接口对活跃 swarm 返回准确计数，并在任务结束或派发后及时更新。
- `scripts/verify.sh` 通过；相关单元测试覆盖新建/复用区分、清理失败与本地记录保留。

# 范围外

不改会话页视觉样式（下一子任务实现），不改启动表单字段，不动 Trellis 与 worker 流程。
