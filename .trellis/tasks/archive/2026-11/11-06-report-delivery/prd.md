# 目标

工单完成、失败、需要人决策或等待输入时，消息必须回到发起它的那个主会话，而不是落在一个固定的 legacy master 会话里。

# 现象

主会话直接派发工单（没有对应 Swarm）时，工单结束后报告已生成，但发起会话没有收到任何消息；报告与 attention 被投递到 `masterId` 指向的会话，该会话与用户当前对话的会话不是同一个，因此无人看到。

# 要求

- 记录每个工单的发起会话；派发时若没有 Swarm，用它作为该工单的消息归属。
- 报告的送达目标按以下顺序解析：工单所属 Swarm 的 master → 派发该工单的会话 → 无归属时不投递并记录可诊断的错误，绝不静默丢弃。
- 覆盖 ready、blocked、failed、dropped 报告与 attention、delivery failure 通知；消息进入发起会话时与其线程一致，可在会话中直接看到上下文。
- 跨重启仍然有效：归属信息持久化，恢复后继续投递；已存在但没有归属字段的工单按现有 legacy 行为处理，不得因此报错。
- 投递失败要暴露在 health 或日志中，不得吞错。
- 修复后，从任意主会话派发的工单结束即可在该会话看到报告，与 Swarm 场景行为一致。

# 验收

- 复现路径：在非 Swarm 的主会话派发一个工单，完成后该会话收到报告消息。
- 有 Swarm 的工单仍送到对应 Swarm 的 master；legacy 记录不报错。
- 单元测试覆盖归属解析顺序、缺失归属与投递失败；`scripts/verify.sh` 通过。

# 范围外

不改 Trellis 规划与工具体系，不改派发预算，不改面板展示。
